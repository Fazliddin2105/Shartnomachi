### U2.1 What changed in behaviour

- **Contracts with terms contrary to law are never created.** The `acknowledge_red` override is gone: `generate` and `agree` return `illegal_clauses` while red findings exist. Remove any «baribir yaratish» (create anyway) confirmation; show the red findings and their `fix_suggestion` instead.
- **Each side edits only its own data once both sides are in:** `party_a.*` is A's, `party_b.*` is B's, everything else is shared terms. Editing the other side's field returns `field_not_yours`.
- **Any change of the terms voids previous consents.** The other side gets a notification.
- **With both sides in, the common contract is produced by consent.** Each side calls `agree`; the second consent generates version N automatically and both sides are notified («Umumiy shartnoma tayyor»). Manual `generate` then returns `agreement_required` until both agreed. A solo draft (other side not invited/joined) can still be generated by the initiator as before.
- **Once every party has signed**, the contract becomes `active` and is filed into **each user's personal archive**.
- **Live warnings next to fields:** every `saveAnswers` response now has `field_warnings: {fieldKey: [{severity, message, fix_suggestion}]}`.

// n.my_side 'A'|'B'

### U2.3 Builder and contract modal changes

1. **Field ownership.** Render questionnaire inputs as before, but disable those with `editable === false` (keep their look; add the `disabled` attribute only). Next to a section owned by the other side, show a muted «2-tomon to'ldiradi».
2. **Live warnings.** Show `field_warnings[key]` under the input as a small `.hp-rule-item` with the severity class (red → `hp-rule-red`, yellow → `hp-rule-amber`, blue → `hp-rule-blue`). Keep the overall list in `#cb-rule-alerts-list`.
3. **Clearing a field** (empty input or a «tozalash» ✕ if the design has one) sends `null`: `saveAnswers(id, {[key]: null})`. It becomes missing again.
4. **Objection** (B, or A on B's proposals). Button «Norozilik bildirish» opens a modal with:
   - a textarea `comment` (required);
   - optional «taklifim» inputs for the fields concerned, rendered like the questionnaire inputs.

   Submit with `contracts.object(id, {comment, fields:[keys], proposed:{key: value}})`.
   For the other side, each open objection is a card with «Qabul qilish» (`resolveObjection(id, oid, 'accept', note)` applies the proposed values) and «Rad etish» (`'reject'`). The author sees «Qaytarib olish» (`'withdraw'`).
5. **Consent.** «Shartlarga roziman» calls `contracts.agree(id)`:
   - `waiting_for` not empty → toast «Rozilik saqlandi. 2-tomon kutilmoqda»;
   - `generated` → toast «Umumiy shartnoma tayyor (vN)», then open the signing step.
6. **Timeline** (inside the contract modal, existing `.hp-timeline-*` pattern): `contracts.timeline(id)` → `{text, at}` (text is ready-made Uzbek).
7. **Invitation preview** (party B before joining): `invitationPreview(pid)` now also returns `warnings[]` (`severity`, `message`, `fix_suggestion`) and `risk_counts`. Show them above «Qabul qilish» so B sees risky points first.

### U2.4 Personal archive

- `LexLab.archive.list({q, type_code})` → `[{id, contract_id, title, side, counterparty, total_amount, currency, version, sha256, signed_at, note, tags, contract_status}]`.
- `LexLab.archive.get(id)` adds `integrity.intact` (document hash re-checked) and `signatures[] {side, method, signed_at}`.
- `LexLab.archive.update(id, {note, tags})` — private note/tags of this user.
- `LexLab.archive.download(item)` — the signed DOCX.

**Placement without design changes:** use the existing `#view-archive` screen. For every user, render «Mening arxivim» there with the existing `.hp-case-step-card` pattern (title, counterparty, signed date, «SHA-256 tasdiqlangan ✓», buttons «Ko'rish» / «Yuklab olish»). For lawyers, keep the case-file timeline below it. Do not rename the sidebar label; the owner decides that separately.
